# こえタイプ

fnキーを押して話し、もう一度押すと、AIが清書した文章がカーソル位置に貼り付く。
Typeless／ぽちペタと同じ使い勝手を自分の環境で動かすもの。

## 使い方

1. `/Applications/こえタイプ.app` を起動（メニューバーにコーラルのCアイコンが出る。Dockには出ない）
2. 文章を入れたい場所をクリックしてカーソルを置く
3. **fnキー（キーボード左下の角にある 🌐 のキー）を1回押す** → 話す → **もう1回押す**
4. 画面下のアイコンで状態が分かる → カーソル位置に文章が入る

| 画面下の表示 | 状態 |
|---|---|
| コーラルのC ＋「録音中」が点滅 | 録音中 |
| 青いC ＋「整え中」が点滅 | AIが文章を整えている |
| 消える | 完了。カーソル位置に貼り付け済み |

メニューバーのアイコンは状態によらず固定（コーラルのC）。状態は画面下の表示だけで示す。

- 押しっぱなしにする必要はない。押すたびに開始と終了が切り替わる
- 清書中にfnを押しても無視する（誤操作防止）
- 止め忘れても `max_seconds`（既定120秒）で自動的に打ち切る
- 表示はフォーカスを奪わない浮遊パネルなので、入力先のカーソルはそのまま

## 最初の1回だけ必要なこと

| 何 | 何のために要るか | どこで許可するか |
|---|---|---|
| マイク | 声を録るため | 初回に出るダイアログで「許可」 |
| 入力監視 | ホットキーの押し下げを検知するため | システム設定 → プライバシーとセキュリティ → **入力監視** → こえタイプ をオン |
| アクセシビリティ | ⌘Vを送ってカーソル位置に貼るため | システム設定 → プライバシーとセキュリティ → **アクセシビリティ** → こえタイプ をオン |

入力監視とアクセシビリティは別物で、**両方が要る**。
片方だけだと「キーを押しても無反応」か「文章はできるが貼られない」のどちらかになる。
許可したあと、いったんアプリを終了して起動し直す。

アプリを別の場所に移動すると、macOSは別アプリとみなして許可がリセットされる。
`/Applications` から動かさないこと。`~/Documents/Claude` はGoogle Driveの同期対象なので、
アプリ本体をあそこに置くと同期のたびに同じ問題が起きる（開発用のソースは置いたままでよい）。

## 設定

メニューバーのアイコンを押すと、状態がその場で読める。

```
fn（地球儀）で録音開始・もう一度で終了
直前: 17文字を貼りました          ← うまくいかなかった理由もここに出る
─────────────────
マイク: ○○のAirPods Pro（自動） ▸  ✓ 自動（システムの既定）
直前の結果をコピー                    MacBook Airのマイク
言葉を覚えさせる…                     ○○のAirPods Pro
─────────────────                   …
終了
```

**「結果をコピー」** には直前3件が本文つきで並ぶ。1件あたり**5行に折り返して**
表示するので、長い文章でも書き出し150文字ほどが読める。マウスを乗せれば全文が出る。
クリックするとその全文がクリップボードに入る。

```
15:40  350文字
例えば直近だと29日と24日に祝日としては初めての開催となるリリー
スイベントを予定しています。 新しいフードだったり、アパレル
…
```

同じ内容は重複せず先頭に来る。`history.json`（本人のみ読める権限）に残るので、
アプリを閉じても消えない。件数は `HISTORY_MAX`、見せる量は `PREVIEW_COLS`（1行の
文字数）と `PREVIEW_LINES`（行数）で変えられる。

**「言葉を覚えさせる…」** で表記を登録できる。1行1件。

```
ぽちぺた、ぽちペタ
げんきAI、Genki AI
```

- 区切りは `→` `->` `>` `=` `、` `,` のどれでもよい。**日本語入力のまま「、」が一番速い**
- 改行は **Shift ＋ Return**（Returnだけだと保存されて閉じる）
- `;` で区切れば1行に複数件まとめてもよい

登録すると、①AIへの指示にこの表を渡す ②清書後に必ず機械的に置き換える の二段構えで直る。
AIが指示に従わなくても②で確実に直るので、一度覚えさせれば次から間違えない。

**「えっと」などのつなぎ言葉も同じ二段構えで落とす。** 清書AIはたいてい消してくれるが、
長い録音では素通しすることがある（実測 2026-09-25: 2分6秒・662文字に「えっと」「ま、」
「うん、うん、うん、うん。」が大量に残った）。そこで清書のあとに、
**「、」「。」で区切られたかたまりが丸ごとつなぎ言葉のときだけ**落とす。
文の途中に埋まっている語は触らないので、意味のある「まあ」「はい」は残る。
消す語は `remove_fillers` / `filler_words` で変えられる。

**マイクはサブメニューから直接選べる**（今使っているものにチェックが付く）。
抜き差しすると一覧も自動で更新される。通知は環境によって出ないので、状態はすべてメニューに出す。

細かい設定は「設定ファイルを開く」（`~/Library/Application Support/KoeType/config.json`）

| 項目 | 意味 |
|---|---|
| `provider` | `auto`（既定）／`gemini`／`openai`。autoはGeminiキーがあればGemini、無ければOpenAI |
| `gemini_api_key` | AI Studioの無料キー。**請求先に紐づいたプロジェクトで作ると前払いクレジット扱いになり429で弾かれる**。請求先なしの新規プロジェクトで作ること |
| `gemini_model` | `gemini-3.1-flash-lite`（既定）。**2026-05-07に廃止告知済み・最短2027-05-07で停止**。後継は `gemini-3.5-flash-lite` |
| `gemini_fallback_models` | 枠が尽きたときに順に試すモデル。**無料枠はモデルごとに別**なので、これで使える回数が増える。**モデルは停止する**ので足す前に廃止予定表で存在を確かめる（ https://ai.google.dev/gemini-api/docs/deprecations ）。`gemini-3.1-flash-lite-preview` は2026-05-25に停止済みで、予備に入れていたため2026-09-10に外した |
| `corrections` | 覚えさせた表記。メニューの「言葉を覚えさせる…」から編集する |
| `hold_key_code` | 押しっぱなしにするキー。63=fn（既定）／61=右Option／58=左Option／54=右Command |
| `vocabulary` | よく使う固有名詞。誤変換が出た語をここに足すと直る（例:「ロウリュウ」） |
| `audio_device` | `auto`（既定）でシステムの既定マイクに自動追従。マイク名を書くとそれに固定。ふだんはメニューから選ぶ |
| `debug_keys` | `true` にすると押されたキーのコードをログに出す。キーを変えたいときに使う。**ふだんは `false`**（Command・Shiftを押すたびに1行増えてログが埋まる） |
| `remove_fillers` | `true`（既定）で「えっと」「ま、」「うーん」などのつなぎ言葉を清書のあとに必ず落とす。消してほしくないときだけ `false` |
| （`filler_words`） | 消す語の一覧を自分で決めたいときだけ書く。書かなければソース側の既定を使う。足すだけなら `extra_fillers` |
| （`HISTORY_MAX`） | コピー用に残す結果の数。既定3。ソース側の定数 |
| （`PREVIEW_COLS` / `PREVIEW_LINES`） | メニューに見せる量。既定は1行30文字×5行。ソース側の定数 |
| `max_seconds` | 1回の最長録音（既定1800秒＝30分） |

### 貼り付けが効かなかったとき

⌘Vを合成して貼るしくみなので、次のときは貼れない。**黙って消えないよう、
そのときは文章をクリップボードに残したまま**「貼り付けできませんでした」と知らせる
（音も鳴る）。貼りたいところで ⌘V を押せばよい。

- パスワード欄など、macOSの**「安全な入力」**が働いているとき
- アクセシビリティの許可が外れているとき
- 前面のアプリが⌘Vを受け取らなかったとき

貼れたかどうかは、カーソルのある入力欄の文字数が変わったかで確かめている。
アプリによっては教えてくれない（ログに「届いたかは確認できません」と出る）。
その場合でも、**クリップボードを元に戻すまで十分に待つ**ようにしてある。
ここを急ぐと、貼り付け先が読み終える前に中身が入れ替わって何も貼られない。

## 速度（2026-09-05 実測）

**6分57秒・30段落（すべて内容が異なる）の音声で計測。**

| 経路 | 所要時間 | 取れた段落 | 費用 |
|---|---|---|---|
| **Gemini 3.1-flash-lite**（既定） | **8.5秒** | **30/30** | 0円 |
| OpenAI（文字起こし＋清書の2回） | 19.3秒 | 30/30 | 約5円 |

短い発話（26秒）ではGemini 3.09秒 / OpenAI 4.44秒。
Geminiは1回のやり取りで文字起こしと清書を済ませるので、**音声が長いほど有利**。

**検証で気をつけること: 同じ内容を繰り返した音声で測ってはいけない。**
AIが繰り返しをまとめてしまい、8分の音声が88文字になった（誤って「動いた」と判断しかけた）。
段落ごとに違う内容にして、各段落に「これは◯番目の話です」と名乗らせると正確に測れる。

## Geminiの無料枠（2026-09-05・AI Studioの画面で確認）

**無料枠はモデルごとに別々。** `koetype` プロジェクト（無料枠）の1日あたり上限:

| モデル | RPD（1日） | RPM（1分） |
|---|---|---|
| **Gemini 3.1 Flash Lite（本命）** | **500** | 15 |
| Gemini 3.5 Flash Lite | 500 | 15 |
| Gemini 3 Flash | 20 | 5 |
| Gemini 3.5 Flash | 20 | 5 |
| Gemini 3.8 Flash（= flash-latest） | 20 | 5 |

**制限は「回数」であって長さではない。** 1秒の録音も10分の録音も1回。
短く何度も使う方が枠を食うので、長く喋る使い方はむしろ有利。
TPMは25万/分。10分の録音1回で約1.5万トークンなので余裕がある。

本命が1日500回あるため、実用上は枠を気にしなくてよい。
念のためモデルを順に切り替える作りにしてあり、429を受けたモデルは30分スキップする。

**このプロジェクトには支払い情報が紐づいていないので、枠を使い切っても課金されない。**
全モデルが尽きたら失敗して音声を残すだけ。AI Studioの「お支払い情報を設定」は押さないこと。

**キーを作る場所も重要。** Cloudの請求先アカウントに紐づいたプロジェクトで作ると、
無料枠ではなく前払いクレジット扱いになり `429 prepayment credits are depleted` で一切使えない。
AI Studioの「＋プロジェクトを作成」で作った素のプロジェクトのキーを使うこと。

速度を戻したいときの過去の落とし穴:
- `whisper-1` は `gpt-4o-mini-transcribe` の3.5倍遅い（2.18秒 vs 0.61秒）うえ精度も低い
- 音量測定でffmpegを起動すると毎回0.07秒かかる。WAVを直接読めば0秒

`ffmpeg` を名前だけで呼ぶと見つからず、fnを押しても無反応になる（通知も出ない）。
`FFMPEG` 定数で絶対パスを解決してある。外部コマンドを足すときは同じ扱いにすること。

```bash

```


## うまく動かないときの読み方

ログの1行目を見れば、どこで詰まっているか分かる。

| ログ | 意味 | 直し方 |
|---|---|---|
| `入力監視=NG` | キーが届いていない | システム設定 → 入力監視 で許可 |
| `アクセシビリティ=NG` | 貼り付けができない | システム設定 → アクセシビリティ で許可 |
| `マイクの許可: 拒否` | 録音しても無音になる | システム設定 → マイク で許可 |
| `キー検知: keycode=NN` が出ない | キーが届いていない | 上の入力監視を確認 |
| `キー検知` は出るが録音しない | 押しているキーが設定と違う | ログのkeycodeを `hold_key_code` に設定 |
| `声が入っていないので送信しませんでした（…起伏◯dB）` | 声が入っていない | 話していたのに出るならメニューでマイクを選び直す |
| メニューバーから🎤が消えた | 起動時に落ちた | ログの「起動に失敗しました」を見る |

**許可はオンなのにNGと出る場合**は、古い署名に対する許可が残っている。下で消してから許可し直す。

```bash
tccutil reset Accessibility com.otolab.koetype
tccutil reset ListenEvent com.otolab.koetype
tccutil reset Microphone com.otolab.koetype
```

## 作りの要点

- 声が入っていない録音はAIに送らない。送ると「ご視聴ありがとうございました」「試験勉強の合間に。」等を捏造するため
- 判定は平均音量ではなく**起伏（上位フレーム － 下から2割のフレーム）が7dB未満か**で行う。MacBook Air本体マイクは自動ゲインで無音でも平均-43dBまで持ち上がり、発話(-42dB)と1dBしか違わず平均では分けられない。実測の起伏は 無音4.8dB／キー打鍵のみ5.3dB／スピーカー越しの音声14.3dB／人の肉声27〜38dB
- 録音デバイスは毎回システムの既定を見に行く。番号固定にすると、AirPods使用中に本体マイクを録って無音になる（実際に起きた）
- 画面表示は非アクティブパネル（フォーカスを奪わない・マウスを素通しする）。奪うと貼り付け先が変わってしまう
- 清書は「短い一言でも必ず出力する」と指示する。「聞き取れなければ空文字」と書くと、AIが短い発話を捨てて何も貼られなくなる（実際に起きた）
- 清書が空を返しても、文字起こしが取れていればそれをそのまま使う（言葉を落とさない）
- 6MBを超える音声はMP3（32kbps）に変換してから送る。13MB→1.6MBに縮み、APIの送信上限を回避できる
- 混雑（503）や枠切れ（429）は数回やり直す。それでも駄目なら音声を `last_failed.wav` に残し、メニューから再送できる
- 音量測定は最大20万点に間引く。7分の録音でも0.009秒で終わる
- **押してから実際にマイクが開くまで0.26〜0.28秒かかる。** その間の声は録れないので、開いてから合図を鳴らす
- 設定ファイルは一時ファイル＋差し替えで書く。壊れていたら `config.json.broken-日時` に退避してから既定値で起動する（黙って上書きするとAPIキーが消える）
- クリップボードの復元はロックで直列化し、`changeCount` で他アプリの割り込みを見る。文字だけでなく全種類を退避する（画像やファイルを壊さないため）
- キー監視のタップは `kCGEventTapDisabledBy*` を受けたら張り直す。放置するとスリープ復帰後にfnが効かなくなる
- メニューの文字はメインスレッドから変える（`AppHelper.callAfter`）。別スレッドから触ると描画が崩れる
- 通信は接続10秒・応答180秒・全体240秒で打ち切る。無制限にすると電波が切れたとき何十分も固まる
- **失敗した音声は `last_failed.wav` に残してメニューから再送できる。** この経路では入力と保存先が同じファイルになるので、コピーも削除もしないよう分岐が要る
- 別スレッドから画面を触るときは `AppHelper.callAfter` でメインスレッドに渡す
- rumpsのサブメニューは、中身を1つも入れないうちは `clear()` できない（起動時に落ちる）
- 通知（`rumps.notification`）はこの環境では出ない。状態はメニュー項目のタイトルに出す
- 清書は「フィラーを消す・言い直しを統合する・誤変換を直す」だけ。内容を足さない・要約しない
- 貼り付けはクリップボード経由。元のクリップボードは0.6秒後に戻す
- 音声もテキストも端末とAPI提供元の間だけで、他所のサーバーは通らない
- **ただしGeminiの無料枠は「学習に使われる枠」。** 公式規約（ https://ai.google.dev/gemini-api/terms ）に、
  無料枠（Unpaid Services）で送った内容は製品改善・機械学習に使われ、人間のレビュアーが読むことがあると明記。
  Google自身が「機微情報・秘密情報・個人情報を無料枠に送るな」と書いている。有料枠は学習に使われない。
  **配布資料には必ずこの事実を書くこと**（受講生は顧客名や未公開の企画を喋る可能性がある）

### 配り方の設計

**アプリを直接渡さない。スキルがコマンド経由で取得する。**

Gatekeeperが止めるのは「隔離の印」が付いたファイルだけ。実測（2026-09-07）:

| 入手方法 | 隔離の印 | 「開発元を検証できません」 |
|---|---|---|
| curl / urllib | **付かない** | **出ない** |
| git clone | **付かない** | **出ない** |

### 展開は必ず ditto を使う

**Pythonの `zipfile` は日本語のフォルダ名を壊す**（`こえタイプ.app` → `πüôπüê…`）。
実行権限も落ちる。`/usr/bin/ditto -x -k` なら名前・権限・署名がそのまま復元される。
